# Лабораторная работа № 3
## Тема: чек-лист, классы эквивалентности и граничные значения
## Задание
Составить чек-лист финального шага оформления заказа. Для калькулятора доставки определить классы эквивалентности и граничные значения, составить сводную таблицу сценариев и детализированный чек-лист.
## Ход выполнения
### Задание 1. Чек-лист для веб-формы оформления заказа
Исходные данные: в корзине один товар за 2500 руб. Форма содержит обязательные Email и телефон, выбор курьера или самовывоза, необязательный промокод со скидкой 10%, блок «Итого» и кнопку «Оплатить». Ниже приведены проверки и ожидаемые результаты. Приложение не предоставлено, поэтому фактические статусы не проставляются.
Тариф платного курьера в условии не указан. В таблице он обозначен D. Для исходной корзины скидка равна 250 руб.; при самовывозе итог без скидки — 2500 руб., со скидкой — 2250 руб.

### Задание 2. Тестирование калькулятора стоимости доставки
По условию допустимы положительные веса до 50,00 кг с точностью до двух знаков после точки. В тарифе лёгких посылок написано «0–5 кг», но отдельное правило отклоняет вес ≤ 0. Поэтому минимальный допустимый вес — 0,01 кг.
#### Часть 1. Классы эквивалентности и граничные значения
Таблица 2. Классы эквивалентности для веса
| Класс | Значения | Представитель | Границы и соседние значения |
|---|---|---|---|
| ЭК1, допустимый | 0,01–5,00 кг; 300 руб. | 2,50 | 0,00; 0,01; 0,02; 4,99; 5,00; 5,01 |
| ЭК2, допустимый | 5,01–20,00 кг; 300 + 50 руб. за полный кг сверх 5 | 10,00 | 5,00; 5,01; 5,02; 19,99; 20,00; 20,01 |
| ЭК3, допустимый | 20,01–50,00 кг; 1050 руб. | 35,00 | 20,00; 20,01; 20,02; 49,99; 50,00; 50,01 |
| ЭК4, недопустимый | Вес ≤ 0 | 0,00 | −0,01; 0,00; 0,01 |
| ЭК5, недопустимый | Вес > 50,00 кг | 50,01 | 50,00; 50,01; 100,00 |
| ЭК6, недопустимый формат | Более двух знаков после точки | 1,234 | 1,23; 1,234 |
| ЭК7, недопустимый ввод | Пусто, буквы, запятая | abc | Пусто; abc; 1,5 |
ЭК1–ЭК5 — числовые интервалы. ЭК6 и ЭК7 описывают отдельные варианты некорректного формата поля. Для каждого класса выбран представитель; на границах добавлены соседние значения с шагом 0,01 кг. Сумма для 5,99 кг равна 300 руб., а для 6,00 кг — 350 руб., потому что оплачиваются только полные килограммы сверх пяти.

#### Часть 3. Детализированный чек-лист
##### Функциональное тестирование — позитивные сценарии
Проверить сценарии 1–9 из таблицы 3. Дополнительно рассчитать 5,99 кг (300 руб.), 6,00 кг (350 руб.) и 7,30 кг (400 руб.), чтобы проверить правило полных килограммов. Повторный расчёт с новым весом должен заменить старый результат.
##### Валидация и обработка ошибок — негативные сценарии
Проверить сценарии 10–13. Для веса 1.234 ожидается ошибка точности; для пустого поля — сообщение об обязательном вводе. После ошибки прежняя стоимость не должна оставаться на экране как результат нового расчёта.
##### Поле ввода — UI/UX
Проверить ввод цифр и точки, ограничение двумя знаками после точки, запрет букв и запятой. Поле и кнопка расчёта должны быть доступны с клавиатуры; сообщение об ошибке должно указывать причину и допустимый диапазон.
##### Дополнительные нефункциональные проверки
1. Рассчитать вес 50,00 кг двадцать раз подряд: результат остаётся 1050 руб., интерфейс не зависает.
2. Дважды быстро нажать кнопку расчёта: один результат, без дублирования сообщений.
3. Открыть калькулятор на узком экране: поле, кнопка, результат и ошибка читаются и не перекрываются.
Все пункты этой части — проект тестов. Адрес работающего калькулятора в задании не дан, поэтому результаты выполнения и скриншоты не заявляются.
